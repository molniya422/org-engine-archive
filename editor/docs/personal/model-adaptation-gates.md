# 模型适配门槛（P7.4）

本文规定：**在什么条件下，才允许考虑用「训练模型」改进个人助手**。
结论先行：当前阶段（P7）不做任何模型微调；改进只允许发生在
路由、检索、规则和提示层。

## 1. 改进顺序（必须从上往下逐级穷尽）

在考虑触碰模型之前，以下手段必须已被证明不够用：

| 层级 | 手段 | 例子 | 产物 |
|---|---|---|---|
| 1 | 路由 | 任务分流到更合适的执行路径 | router 版本 |
| 2 | 检索 | 证据召回排序、来源过滤 | 检索配置版本 |
| 3 | 规则 | 硬约束、偏好规则（P7.2/P7.3） | 规则版本 |
| 4 | 提示 | 提示模板迭代 | prompts 版本 |
| 5 | 模型 | LoRA / 蒸馏实验 | **本阶段禁止** |

1–4 层都具有共同性质：**可审计、可回滚、可逐字审阅**。第 5 层不满足
这三条中的任何一条，所以它排在最后，且门槛最高。

## 2. 启动 LoRA/蒸馏实验的前置门槛（全部满足才可开始）

1. **信号充足**：足够多的高质量行为信号（accepted/repeated_correction），
   覆盖真实任务类型，而非少数场景反复出现。
2. **个人 eval 稳定**：`engine/personal/eval_runner.py` 的个人回归集在
   连续多轮上结果稳定（无 flaky），失败案例已逐条归因。
3. **低层收益递减**：路由/检索/规则/提示层面已无已知的可改进项。
4. **用户逐项 opt-in**：训练数据默认不收集；用户显式勾选「允许把我的
   行为信号用于模型实验」后才进入候选池。
5. **数据可导出、可删除**：导出格式为带 evidence 引用的 JSONL；删除后
   不留副本。

## 3. 替换原模型的门槛

实验模型不得直接上线，替换前必须：

1. **并行回放**：微调模型与原模型对同一批历史任务（含个人 eval 全集）
   并行执行，逐项比较结论、证据引用与越权行为；
2. **不劣于原模型**：eval 通过率、证据引用正确率、越权率三项均不劣于
   原模型；
3. **保留原模型回滚路径**：替换 Must 是版本事件——旧模型版本保留，
   回滚后重新执行同一任务时使用旧版本（复用 P7.3 版本账本语义）；
4. **审计**：替换记录提案号、eval 报告、回滚指令。

## 4. 与「学习规则」的边界（一句话）

规则是写得出来的偏好，训练是写不出来的模式——**写得出来的一律用规则；
只有规则无法表达、且证据充分时，才进入本章门槛。**
